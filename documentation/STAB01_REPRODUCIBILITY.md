# STAB01: conditional refitting-stability code

This is an adaptation of historical STAB01 execution source, not an original run record or proof of numerical reproduction. STAB01 was a separately specified secondary extension, after the Phase I analysis and before perturbation results were examined. The fixed-cohort cross-fitted ranking is conditional on the observed cohort, fixed community-grouped folds and the defined training-community perturbations. It does not establish clinical utility, prospective validation or causal mechanisms; perturbation percentiles are not population confidence intervals.

The historical independent audit verified cohort/fold identity, original membership and recorded sampling draws; it did not independently recompute all model predictions, per-replicate intersections or full empirical distributions. Executor-reported completion of 4,000 fits and baseline reconstruction are not independent numerical verification. Code availability or synthetic tests do not establish complete licensed-source end-to-end reproduction. Existing Phase I estimates and primary comparisons remain unchanged.

## Local use requires separate authorization and trusted restricted inputs

The script is inert on import and rejects optimized Python. Execution requires separate local authorization, `STAB01_RUN_AUTHORIZED=YES`, a private input manifest at `STAB01_PRIVATE_INPUT_MANIFEST`, a private reference at `STAB01_TRUSTED_REFERENCE`, and a locally trusted private authority at `STAB01_PRIVATE_AUTHORITY`. The authority must be an owner-only regular file supplied through a trusted independent process; it is not part of the public package. The guard checks the reference against that authority, then verifies the manifest and actual input bytes against the reference before creating an output directory. It fails closed if the private authority is absent, unreadable or inconsistent. The private authority is JSON with fields `schema` (value `stab01-private-authority-v1`) and `reference_sha256`; its value is supplied privately by the authorized custodian. Never upload the authority, reference, fingerprints or local paths.

The input manifest has exactly `inputs` and `output_dir`. `inputs` has exactly `protocol`, `plan`, `feasibility`, `model_code`, `executed_common`, `analytic`, `oof`, `folds`, `lock`; each value is an object with `path` and `sha256`. Authorized users must establish the authority and reference against the historical frozen contract through the custodian before use. **The public package alone cannot authenticate the private authority or verify historical frozen input identity.** An arbitrary self-consistent authority and reference can pass byte checks and do not establish historical identity. Hashes do not authenticate origin, nor protect a maliciously altered or concurrently modified workspace. Treat all inputs and code as trusted and immutable during execution. Match the historical software and thread settings. Access to original source, folds, predictions and analytic data depends on provider permission and is not supplied here. This code does not authorize execution.

The script writes restricted provenance and draw logs and aggregate results into the specified output directory. Those artifacts can contain sensitive fingerprints or metadata and must not be uploaded without review and permission. No subject-level predictions or membership are exported by this script, but authorized input and in-memory data remain restricted. The original sampling, fixed capacity and overlap code is retained. Independent code review is required before public release.

Synthetic tests: `python -m unittest discover -s tests/stab01 -v`. These do not validate historical estimates or complete pipeline behavior. HRS-CORR01 and existing Phase I code remain governed by their existing records.

The runner dynamically extracts four function definitions from the historical Phase I model source after verifying its identity against the locally trusted private reference. The definitions execute together in an explicitly shared namespace with the required NumPy, preprocessing and logistic-regression symbols; the runner binds those functions for use by the existing fit and ranking code. This is not a sandbox: it depends on the guard, source integrity, and a trusted, non-concurrently modified local workspace.
